🛣️ SostaApp Production ADK Runner — Complete Feature Guide

How the custom FastAPI Runner, FirestoreSessionService, FirestoreMemoryService, New/Returning User Workflows, and Distributed A2A + MCP + Vertex AI RAG Microservices work together.

1. What Is the Green Badge at the Top of the Chat UI?

🟢 FirestoreSessionService + FirestoreMemoryService (adk-agent-dev-session-memory-fs)

When the Chat UI loads, it queries GET /health on the FastAPI server. This green badge confirms that you are not running on adk web's volatile in-memory defaults (InMemorySessionService). Instead, the ADK Runner is actively wired to two custom production persistence services backed by your Google Cloud Firestore database adk-agent-dev-session-memory-fs:

  • FirestoreSessionService (Collection: sosta_sessions): Persists every turn's Event history, active sub-agent delegation (Gatekeeper → Registratore / Cameriere), and session.state dictionary so container restarts or browser refreshes never lose your conversation.
  • FirestoreMemoryService (Collection: sosta_memories): Archives completed trip conversations across sessions. When a returning user starts a brand-new session_id weeks later, Cameriere's built-in preload_memory tool automatically queries sosta_memories and injects <PAST_CONVERSATIONS> into the system prompt.

3. Supporting Both Returning Users & New User Registration

🆕 Flow A: New User Registration

Starting as an Unregistered Traveler

Click 🆕 New User (Register) in the top toolbar. This sets user_id = "guest" and creates a fresh session_id.

  1. Tell Gatekeeper you are a new user.
  2. Gatekeeper transfers you to Registratore.
  3. Provide your name, email, language, dietary preferences, and vehicle type.
  4. Registratore calls save_new_user(), which creates your permanent record in adk-agent-dev-application-db-fs and assigns a unique ID (e.g., usr_a1b2c3).
  5. Automatic ID Promotion: Both FirestoreSessionService and the Chat UI automatically promote your active user_id from guest to your newly assigned usr_xxxxxx ID!
👤 Flow B: Returning Registered User

Logging in with an Existing ID (e.g. usr_0a8f67)

Click 👤 Returning User (usr_0a8f67) in the toolbar (or type your usr_xxxxxx ID in chat).

  1. Gatekeeper calls is_registered_user(user_id="usr_0a8f67").
  2. Your profile is verified in Firestore and hydrated into session.state["user:*"].
  3. Gatekeeper transfers control to Cameriere, which calls extract_user_profile and automatically loads any past trip memories via preload_memory.
  4. Once you share your origin/destination, Cameriere delegates over A2A HTTP JSON-RPC to Suggeritore on port 8001.

4. Distributed 3-Service Stack (Ports 8000, 8001, 8002)

Port :8000 — FastAPI Runner

Main SostaApp Orchestrator

Hosts Gatekeeper, Registratore, and Cameriere inside our custom FastAPI + ADK Runner backed by FirestoreSessionService and FirestoreMemoryService.

Port :8001 — Remote A2A Server

Suggeritore Microservice

Exposed via to_a2a(agent, port=8001) and consumed via RemoteA2aAgent. Orchestrates RoutePlannerAgent, SosteSearchAgent, and MenuCheckerAgent.

Port :8002 — FastMCP SSE Server

BigQuery Geospatial MCP

Standalone Model Context Protocol server querying soste_app_dev.db_soste in Google BigQuery over HTTP SSE (/sse).

5. Step-by-Step Interactive Walkthroughs in the Chat UI

Walkthrough 1: Onboard a Brand-New User

  1. In the Chat UI toolbar, click 🆕 New User (Register) (notice user_id becomes guest).
  2. Click chip 🆕 1a. New User: Start Registration and press Send.
  3. When Registratore asks for your details, click chip 📝 1b. New User: Send Profile Details and press Send.
  4. Watch the right-hand inspector: save_new_user executes, your new usr_xxxxxx ID is generated, the toolbar user_id field automatically updates from guest to usr_xxxxxx, and control transfers to Cameriere!

Walkthrough 2: Test Cross-Session Long-Term Memory Recall

  1. Click 👤 Returning User (usr_0a8f67) and ensure persist_memory is checked.
  2. Log in with chip 🔑 2. Login Returning User, then send chip 🐕 3. Share Trip & Dog Max.
  3. Click 🗑️ Delete Session (or type a brand-new session_id like trip_november_002 in the toolbar) to prove the active session is gone.
  4. Log in again in the new session and send chip 🧠 4. Test Cross-Session Recall. Cameriere recalls your dog Max and Secchia Ovest from FirestoreMemoryService!
