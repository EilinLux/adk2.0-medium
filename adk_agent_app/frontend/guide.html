SostaApp Production Runner & Web UI Guide

How the motorway stop planner UI (/dev-ui/), ADK Web REST convention (/run, /apps/sosta_app/users/{user_id}/sessions, /memory), FirestoreSessionService, FirestoreMemoryService, and distributed A2A + MCP + Vertex AI RAG microservices work together.

1. Developer Details & Firestore Runtime Service Status

Service status: online (FirestoreSessionService + FirestoreMemoryService · adk-agent-dev-session-memory-fs)

Click the top-right Guest · Sign in (or Signed in · usr_0a8f67) chip and choose Show developer details (or open /dev-ui/?debug=1). This reveals tool-call badges under each reply plus a live bottom inspector drawer showing the Firestore runtime health, active session.state, and last-turn tool calls.

  • FirestoreSessionService (Collection: sosta_sessions): Persists every turn's Event history, active sub-agent delegation (Gatekeeper → Registratore / Cameriere), and session.state dictionary so container restarts or browser refreshes never lose your conversation.
  • FirestoreMemoryService (Collection: sosta_memories): Automatically archives each turn via PATCH /apps/sosta_app/users/{user_id}/memory. When a returning user starts a new chat later, Cameriere's built-in preload_memory tool queries sosta_memories and injects <PAST_CONVERSATIONS> into the system prompt.

3. Supporting Both New Travelers & Returning Users

🆕 New User Onboarding

Creating a Profile as a Guest

When you open /dev-ui/ as Guest and click the Create my profile starter card:

  1. Gatekeeper transfers you to Registratore.
  2. Share your name, email, preferred language, dietary preferences, and vehicle type.
  3. Registratore calls save_new_user(), writing your profile to adk-agent-dev-application-db-fs and generating a unique ID (e.g., usr_a1b2c3).
  4. Automatic Sign-In Promotion: The UI detects verified_user_id in the event stream's state_delta and automatically signs you in as usr_xxxxxx in the top-right chip!
👤 Returning Traveler

Signing In with an Existing ID (e.g. usr_0a8f67)

Click Guest · Sign in in the top-right header and enter usr_0a8f67 (or mention your ID directly in chat):

  1. Gatekeeper calls is_registered_user(user_id="usr_0a8f67").
  2. Your profile is verified in Firestore and hydrated into session.state["user:*"].
  3. Gatekeeper transfers control to Cameriere, which calls extract_user_profile and loads your past trip memories via preload_memory.
  4. When you ask for a stop on your route, Cameriere delegates over A2A HTTP JSON-RPC to Suggeritore on port 8001.

4. Official ADK Web Convention REST Endpoints (Port :8000)

Method & Route Purpose
GET /dev-ui/ (and GET /) Interactive SostaApp motorway stop planner UI (with GET /dev-ui/guide for this guide).
GET /health, GET /version, GET /list-apps Liveness, Firestore runtime service binding check, ADK version, and app discovery.
POST /run & POST /run_sse Executes an agent turn using RunAgentRequest (app_name, user_id, session_id, new_message) returning a JSON list of Events or an SSE stream.
GET|POST|PATCH|DELETE /apps/{app_name}/users/{user_id}/sessions/{session_id} Creates, inspects, updates state_delta, or deletes a persisted session in FirestoreSessionService.
PATCH /apps/{app_name}/users/{user_id}/memory Ingests all events from {"session_id": "..."} into FirestoreMemoryService for cross-session recall.
